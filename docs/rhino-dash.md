# Rhino Dash — `app/games/rhino-dash/`

3D cliff-top typing duel (`@react-three/fiber` + `three`), sibling of
typing-ninja and built on the same architecture. Single entry point:
`/games/rhino-dash` (`page.tsx`, `next/dynamic` + `ssr: false`, fullscreen fixed
overlay). Not embedded in the lesson runtime — arcade only, linked from
`/games`.

Files: `RhinoWorld.tsx` (state, tug-of-war physics, input, HUD, sound),
`rhino.tsx` (loads + animates the rhino GLB), `environment.tsx` (camera
rig, sky, ocean, cliff island, `WORLD` constants, local `getSoftTexture`).
The character model is our own authored asset: `public/models/rhino.glb`,
generated by **`scripts/build-rhino-model.mjs`** (`npm run model:rhino`) —
edit the script and regenerate, never hand-edit the GLB.

## 1. Game design

Two rhinos shove head-to-head on a grass meadow atop a cliff island in the
ocean (a 3D remake of TypingBird's "Rhino Dash"). One word shows at a time
as DOM letter tiles. Every correct letter feeds push force; the rival pushes
back constantly; typos knock you backwards. **Endurance mode, one life**:
shove a rival past the cliff edge and the game does NOT stop — a stronger
rival (`WAVE_RAMP` per wave, capped at `WAVE_RAMP_CAP`) charges in and the
word pool climbs to longer words (`WORD_TIERS`, one tier every `TIER_EVERY`
waves). The moment YOUR rhino goes over the edge the run ends — the summary
shows WPM, accuracy, time survived and rivals defeated.

**Tug-of-war model** (`GameLoop`): the contact point `pushX` moves by
`playerForce − enemyRate` each frame. `playerForce` decays with
`FORCE_TAU` (0.55 s) and each correct key adds `pushPerKey` (+ up to 30%
streak bonus), so holding ground needs a steady keys/sec ≈
`enemyPush / (pushPerKey · τ)`. Difficulty sets `enemyPush`, `pushPerKey`
and the starting word tier (EASY 3–4-letter words → HARD 7–10). Completing
a word adds an instant `WORD_LUNGE` shove; a typo costs `MISS_KNOCKBACK`
and 70% of the built-up force. `|pushX| > WORLD.FALL_X` starts the fall.

**Rage cycle**: every 6–9 s of battle the rival telegraphs (`tele` 0.8 s,
rears up, pushes at 15%, HUD warning) then rage-shoves (`shove` 0.7 s at
2.6×). Gives the duel rhythm and urgency.

**Phases** (`state.phase`, sub-states of `gameState === "PLAYING"`):
`idle` (menu backdrop) → `countdown` (walk-in via `state.entry` — wave 1 is
a 3-2-1-GO with both rhinos entering; later waves are a quick 2-count where
the player walks back from `state.entryFrom` while the new rival charges in
from the right) → `battle` (input active; the WPM clock `battleTimeMs` only
runs here) → `fall` (loser tumbles with gravity, splash at `WATER_Y`,
winner hops) → `roundover` (transient guard; `onFallDone` fires exactly
once → next wave, or GAME_OVER if the player fell).

## 2. Simulation model: refs, not React state

Same contract as typing-ninja (see `docs/typing-ninja.md` §1): one mutable
object from `getInitialState()` in `stateRef`, mutated in `useFrame`; every
frame body clamps `dt = Math.min(delta, 0.1)`. React state is only: the
particle ID list, a ~20 Hz `hudState` snapshot, and `wordState`
(word/typed/errorTick) which **is** updated per keystroke — it drives the
DOM letter tiles and must be instant.

Game-feel channels read by visuals: `pushVel` (lean), `lungeCount` (player
lunge + enemy recoil, same counter), `flinchCount` (player typo recoil),
`ragePhase`/`rageT`, `victor` (celebration hops), `falling` {x,y,rot},
`camTrauma`/`camPunch`, `redFlash`, `entry`.

`GameState = MENU | PLAYING | PAUSED | VICTORY | GAME_OVER`. `GameLoop`
mounts only while PLAYING (pause truly halts falls mid-air). Esc pauses,
Enter restarts from the end screens. Returning to MENU resets
`phase = "idle"` so the backdrop rhinos idle correctly.

## 3. The rhinos (`rhino.tsx` + `scripts/build-rhino-model.mjs`)

The model is a GLB like the ninja's `hero.glb`, but authored in-repo: the
builder script sculpts it from displaced/bent primitives (shoulder hump,
curved horns, fold bands, 3-toed hooves) with per-face normals baked in
(glTF has no flatShading flag), and exports a **named node hierarchy that
is the animation rig**: `Body` (bob/lean/lunge), `Head` (butt tilts),
`Tail` (swish), `LegFR/FL/BR/BL` (hip pivots). There are no skeletal
animation clips on purpose — gait speed must track live typing force, so
the game drives the pivots in `useFrame`. Pivot heights/positions are
duplicated between the script and `rhino.tsx` (e.g. `Body` at y = 1.12) —
keep them in sync when regenerating.

One `Rhino` component, two instances (`variant: "player" | "enemy"`); ONE
GLB serves both: each instance clones the scene (`SkeletonUtils.clone`) and
clones + tints materials **by material name** (Body/Fold/Horn/Hoof/Eye/
InnerEar); the rival gets emissive red eyes and keeps the `BrowL`/`BrowR`
meshes the hero hides. The model faces +X; the enemy is rotated π around Y
so local animation math (nose-down = negative `rotation.z`) is shared. All
motion derives in one `useFrame` from `stateRef`: gait frequency tracks
push force, lean tracks `pushVel · dir`, overlays (lunge/flinch/recoil/rage
rear-up) are timers triggered by counter changes. During `fall` the root
pose comes straight from `state.falling` — `rot` uses the same sign for
both variants (the enemy's π flip mirrors it into an outward tumble).
Blob-shadow opacity fades as `y` drops below the meadow.

## 4. Sound + stats

Inline oscillator `SoundSynthesizer` (module singleton `sfx`), no files:
key tap, stereo hoof stomp per correct letter, typo thud, word-shove whoosh,
rage horns, fall whistle, splash, round/victory arpeggios, defeat descent,
and a look-ahead-scheduled savanna drum BGM (kick/shaker/tom) whose tempo
rises with round number and how close either side is to an edge.

Keystroke stats: `createStatsSession()` per run, `stroke()` on every typed
key (miss attributed to the expected letter); on VICTORY/GAME_OVER the run
is flushed and `recordAttempt({ lessonId: "rhino-dash", type: "game" })`
logs WPM (correct/5/min over `battleTimeMs`), accuracy, errors. High score
persists in `localStorage["tz-rhino-highscore"]`; score = 10/letter per
word + 150 per rival knocked off.

## Invariants

- dt-clamp every `useFrame`; simulation state lives in `stateRef.current`.
- `GameLoop` is the only writer of `phase` transitions, `pushX` integration
  and round outcomes; `Rhino`/`CameraRig` read state (they only decay the
  cam channels they own). The keydown handler is the only writer of
  `word`/`typed`/`playerForce` impulses.
- `onFallDone` fires exactly once per fall (guarded by the
  `fall → roundover` transition). The player falling ends the run
  immediately — there is no second life; a rival falling must always
  start the next wave (the game never stops on a win).
- `battleTimeMs` only advances during `battle` — WPM must not count
  countdowns or falls.
- Particle emitters stay bounded (dust gated at 70 live particles).
- `public/models/rhino.glb` is generated — change
  `scripts/build-rhino-model.mjs` and run `npm run model:rhino`; keep node
  names/pivots in sync with `rhino.tsx`. No mp3s — audio is the synth. Keep
  the local `getSoftTexture` (importing the ninja one would preload its
  GLTFs).
