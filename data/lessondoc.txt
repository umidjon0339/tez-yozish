================================================================================
UNIVERSAL TYPING ACADEMY: MASTER SCHEMA & API SPECIFICATION (v3.0)
ARCHITECTURE: 4-Tier Flat Hierarchy (Course -> Chapter -> Lesson -> Step)
SUPPORTED LOCALES: English (en), Uzbek (uz), Russian (ru)
================================================================================

ATTENTION CURRICULUM DATA ENGINEERS & AI GENERATORS:
This document is the absolute technical standard for creating course content. 
Follow the exact naming conventions, deep-nested object structures, and 
strict validation rules defined below.

--------------------------------------------------------------------------------
PART 1: GLOBAL INTERFACES & DATA TYPES
--------------------------------------------------------------------------------

1. THE TRI-LINGUAL STRING (LocalizedString)
All user-facing instructional text and UI titles must strictly provide translations 
for all three supported platforms. Partial objects will fail compilation.

interface LocalizedString {
  en: string; // English
  uz: string; // O'zbekcha
  ru: string; // Русский
}

2. THE VIEWPORT RENDERER (ViewportMode)
This string dictates exactly which React UI component mounts on the client's screen.

enum ViewportMode {
  POSTURE_CHECK  = "POSTURE_CHECK",  // Static hands graphic; waits for home row anchor
  KEY_INTRO      = "KEY_INTRO",      // Introduces a single new key coordinate
  STANDARD_GYM   = "STANDARD_GYM",   // Standard typing treadmill (letters/words/texts)
  GAME_NINJA_RUN = "GAME_NINJA_RUN"  // 3D WebGL Runner Game (consumes 'content' array)
}

3. THE EXECUTION RULES (StepRules)
Defines the mechanical strictness for completing a Step.

interface StepRules {
  allowBackspace: boolean;     // If true: user can delete mistakes.
  blockOnTypo: boolean;        // If true: cursor freezes until the correct key is struck.
                               // If false: cursor advances, marking the letter red.
  maxMistakesAllowed: number;  // Maximum permitted typos before triggering an instant fail/reset.
                               // Set to 0 for strict flawless execution.
  minimumWPM: number;          // Target speed threshold. Set to 0 to disable timer.
}

--------------------------------------------------------------------------------
PART 2: THE 4-TIER HIERARCHY SCHEMA
--------------------------------------------------------------------------------

TIER 1: ROOT COURSE (CourseNode)
{
  "courseId": string,
  "courseTitle": LocalizedString,
  "targetAudience": string,
  "chapters": [ ChapterNode, ChapterNode, ... ]
}

TIER 2: CHAPTER (ChapterNode)
{
  "chapterId": string,
  "chapterNumber": number,
  "chapterTitle": LocalizedString,
  "description": LocalizedString,
  "lessons": [ LessonNode, LessonNode, ... ]
}

TIER 3: LESSON (LessonNode)
{
  "lessonId": string,
  "lessonNumber": number,
  "lessonTitle": LocalizedString,
  "pedagogicalGoal": LocalizedString,
  "unlockedKeys": string[], // CRITICAL: Content strings in this lesson cannot contain 
                            // characters outside this explicit array.
  "steps": [ StepNode, StepNode, ... ]
}

TIER 4: STEP (StepNode)
{
  "stepId": string,
  "stepNumber": number,
  "viewport": ViewportMode,
  "instruction": LocalizedString, // Top-screen Sensei prompt
  "content": string[],            // The raw data payload (Tokens, Words, or Sentences).
                                  // For Games, each string represents one spawned enemy.
  "rules": StepRules
}

--------------------------------------------------------------------------------
PART 3: COMPILER COMPLIANCE & SAFETY LAWS
--------------------------------------------------------------------------------

LAW 1 (The Key-Vector Boundary): 
If a Lesson declares "unlockedKeys": ["f", "j", "r", "u"], placing the string "run" 
inside a Step's content array is a fatal compile violation. The character 'n' 
has not been unlocked. 

LAW 2 (Token Atomicity):
Never put spacebars inside discrete content strings. Writing "content": ["red fox"] 
is invalid. It must be split into atomic target tokens: "content": ["red", "fox"]. 
The user resolves "red", which instantly snaps the engine focus to "fox".
