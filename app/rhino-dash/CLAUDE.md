# app/rhino-dash/ — the cliff-duel 3D game

Read **`docs/rhino-dash.md`** before editing.

Hard rules:
- Simulation state lives in `stateRef.current` (one mutable object from
  `getInitialState()`), mutated in `useFrame` — React state is only the
  particle ID list, the ~20 Hz HUD snapshot, and `wordState` (which must
  keep updating instantly per keystroke for the DOM letter tiles).
- Clamp `dt = Math.min(delta, 0.1)` in every `useFrame`.
- `GameLoop` mounts only while `PLAYING` and is the sole writer of phase
  transitions / `pushX` integration; `onFallDone` must fire exactly once
  per fall. One life: the player falling ends the run; a rival falling
  always starts the next (stronger, longer-worded) wave — never a win
  screen.
- `battleTimeMs` (the WPM clock) only advances during the `battle` phase.
- The rhino model `public/models/rhino.glb` is GENERATED by
  `scripts/build-rhino-model.mjs` (`npm run model:rhino`) — edit the script
  and regenerate, never hand-edit the GLB. Its named nodes
  (Body/Head/Tail/LegFR…) are the animation rig driven by `rhino.tsx`;
  material tints are looked up by material name. Keep pivots (Body y=1.12,
  hip positions) in sync between the script and `rhino.tsx`.
- No mp3 assets: audio is the inline oscillator `SoundSynthesizer`. Use the
  local `getSoftTexture` from `./environment` — importing typing-ninja's
  would preload its GLTF models.
- Particle emitters stay bounded (~70 live particles).
- The eslint disables at the top of these files are intentional
  (mutable-ref architecture); don't "fix" them.
